## 每日实际执行

1. 读取工作区及子工程AGENTS和本文件，核对新的磁盘/NTFS错误。项目只在D盘运行，新错误出现立即停止业务写入并报告，不能删除旧副本。服务只通过根`dev.ps1 Status/Start`检查或启动，复用原Docker容器和数据卷，不启动另一套Maven环境。
2. 工作区先载入`dev-env.ps1`；切到`03-python`，用`.venv/Scripts/python.exe -B -m app.commands.fund_daily_prediction`推进。首次自动目录为`.local-runs/daily-prediction-YYYYMMDD`；以后始终用返回的同一`--run-dir`。互斥锁防止重复运行。不要把guard、check或导出输入当成已生成。
3. `WAITING_MATERIALS`持续查询原作业到真实终态。纯资料模式不直接生成新评分或预测；检查全部子任务和历史到期核对七项计数。公共资料仍沿用原队列，最终评分和预测仅限本人模拟持仓。
4. 逐基金读取`work-items.json`、`supplement.json`、公告与真实原件。原件已取得但未解析、未整理或未审阅时继续执行，不把可处理工作包装为外部阻断。所需公开补件可有界获取，保留首错和真实取得时刻。资料用途审批用本轮真正阅读形成的`--reviews-file`，不自动填批准。
5. 阅读每个周期冻结的`input.json`及引用原文，独立写主要依据、反证、权衡、不确定性和改变条件，形成标准哈希`review.json`。再次执行原命令导入并通过正式Java本人归档。不能用公式或旧净值模型代替综合审阅，不能复制短周期到长周期。
6. 原命令在资料终态后处理持仓月度评分并独立读回。月度以最近结束月的实际估值日为截止；同资料复用，缺期资料继续补齐。`ratings-status.json`中的事项或缺项仍须继续处理：按原文逐件审阅，新资料用正式编译与`fund_ratings register-update`登记；有真实重大影响时沿用`fund_ratings update --fund-code <持仓代码> --as-of <真实日期> --event-review`追加复核。每次执行前再次核对该代码仍在本人模拟持仓。不可全市场重评或为了显示总分降低八维门槛，事件复核完成后重新运行原续办命令读回。
7. 最终`CLOSED`只代表预测守卫已关闭；`all_predictions_generated=true`才代表全部周期生成。评分部分完成、缺到期核对摘要或漏项不得称整轮成功。持仓评分同时保存`scope`和逐基金正式读回。

## 09:50独立核对与反馈

在相同D盘环境执行`python -B -m app.commands.fund_daily_check`。它不启动服务或生成结论；真实交叉核对当前模拟持仓、今日运行目录、原资料终态、四周期原结果和本人归档、当前资料摘要、正式评分与历史到期核对摘要。回执保存在`.local-runs/daily-checks/YYYYMMDD.json`。没有今日run.json报`NOT_STARTED`；服务不可用、持仓变化、旧日期、缺失回执、缺分、未生成或外部阻断均明确反馈，不能默认为成功。

每天用通俗中文反馈：持仓基金数，资料是否完成，评分完整/部分/缺失及日期，四个周期实际保存数，仍缺哪些资料或日历，历史预测到期核对情况。检查时尚在运行就报告仍在运行，不把进度100%当成功。若继续原作业，始终保留09:50当时的事实，不补写当时已成功。
