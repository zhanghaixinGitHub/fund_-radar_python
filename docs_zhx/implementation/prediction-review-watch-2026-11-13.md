# 暂不判断的变化重审与完成状态

2026年11月13日，用户同意将“已分析、等待关键变化”接入每日更新和检查。承接[华商两项补核](prediction-v2-convertible-continuation-2026-11-13.md)。

## 工作方式

本人当前正份额持仓每轮动态读取。只观察最新正式分析中暂不判断的周期，不把基金代码或数量写死。已清仓基金不新增待办，旧证据保留。

1. 从正式档案中核对已审阅材料的身份。严格发布使用已有材料摘要；首次九只试验沿原摘要链核对输入、来源、D盘材料。首次观察不能把未读的新包当成已读基线。
2. 比较当前已登记材料的实际输入摘要。仅用途批准说明和批准时间变化不产生新经济证据；其余字段保守参与判断，不悄悄丢弃来源、日期、内容或缺口。
3. 相同资料保持观察，不生成新分析，不改写观察文件。资料变化生成一份绑定本人、基金、周期、原窗口和新资料的重审待办；重复检查同一版本复用同一待办。
4. 新资料需要实际阅读和比较主次，不能自动推方向、自动批准或把首次发现时间当分析时间。一方略占优势可给低把握方向，不要求消除普通未来风险；真实主次仍未分清可继续暂不判断。
5. 原窗口结束后停止方向重审，保留历史。半年名义日期不替代实际结束估值日；名义日期到达而实际日历未齐时明确等待官方日期。

观察命令不采集外部资料，材料未登记、交接失效或原文摘要不符时报告检查失败，不能称“没有变化”。正常资料取得仍沿每日既有资料流程执行。

## 执行与09:40检查

正常每日续办的最终核对已接入变化观察。独立命令：

```powershell
. .\dev-env.ps1
Set-Location .\03-python
.\.venv\Scripts\python.exe -B -m app.commands.fund_prediction_review_watch
```

单独命令也适用于当日主任务漏跑或已错过窗口时，检查旧分析是否有变化；不会关闭或更换原每日目标窗口。观察记录写`.local-runs/prediction-review-watch/<本人摘要>/<基金>/<周期>.json`，旧状态按原版本保存机制留档。没有变化不写新版本。

主任务读取`reassessment_watch.items`，只处理`review_required=true`的项目，沿用其中的`original_period`，阅读`current_materials_path`和实际新来源，分别重审主要依据、反证与改变条件。它是原窗口继续研究，不拿新日的严格请求冒充原窗口分析，也不倒填日期。新一期预测继续走原`fund_prediction_v2_sources`、`prepare/evaluate`及正式发布流程。

原窗口继续研究的`research-packet.json`应在实际审阅完成后保存：

```json
{"reviewed_materials":{"基金代码":{"materials_path":"D盘本次实际审阅包的绝对路径","materials_hash":"完整材料包摘要"}}}}
```

该研究包必须随正式档案保存。观察器逐周期从正式存档核对这个绑定；未保存新绑定不能自动消除新资料待办。仍暂不判断也可结束本次审阅，但不是有方向预测。独立检查只保存检查/观察回执和反馈，不生成、发布新评分预测，不额外提交资料作业。

00:30执行与09:40检查的原任务只补充这些处理和反馈规则，时间、原聊天、通知偏好及其他业务范围不变，不创建新定时任务。

## 状态与计数

- `review_complete`表示已审阅，`direction_available`表示有方向，两者独立。
- 修正半年暂不判断的优先级：计入`REVIEWED_ABSTAIN`，不混入有方向的半年条件意见。
- 每日分别输出已审阅、未审阅、带日期方向、半年条件方向、暂不判断、新资料重审待办及检查失败数量。
- 第二版独立检查以审阅是否齐全核对处理完成；暂不判断不再被误报为漏跑。`all_predictions_generated`仍如实为假，不因审阅齐全变成全部有方向。
- 新材料产生的新请求绑定材料输入摘要，旧资料发布不能完成新资料请求。
- 旧窗口的两项观察不用于关闭新一期四周期。观察失败和出现重审待办单列反馈。

页面沿用原四卡，只补“已审阅 · 暂无方向”、上次分析时间和“出现哪些变化后重新判断”。半年暂不判断显示“半年分析”，不再同时说已给出条件方向。未生成、读取失败、旧区间和半年终点待核分别保留。
