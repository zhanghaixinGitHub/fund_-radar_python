## 点击更新后怎样处理

“更新预测”登记当前窗口的新请求，先核本人当前真实持仓和所需基准净值。

- 净值未齐，说明等待新基准净值和资料，仍显示原分析日期。
- 净值已齐但尚未实际读完资料，说明等待审阅，不宣布更新完成。
- 新的严格审阅正式保存并读回后，更新对应请求进度。半年条件意见和暂不判断分别计数，不当成带日期方向。
- 新分析必须对应当前账号、规则、资料和窗口。旧36项不能关闭新一期请求，过期补写也不能变回事前预测。

页面读取失败和没有分析分别提示；切换基金时，晚到的旧响应不会覆盖新基金。

## 每日任务继续怎样执行

每日执行与独立检查的操作说明已同步到第二版。本轮只改预测步骤，保留现有时间、持仓范围、通知偏好及所属聊天；检查任务的并发更新未被旧配置覆盖。评分、历史核对和收益等原授权不扩大；不启动训练、交易结算或清理。

日常仍先运行`app.commands.fund_daily_prediction`，同一期继续原目录，不另起重复资料批次。新版运行器会生成当前材料、规则、本人身份和窗口绑定的`analysis-request.json`。

实际审阅按以下步骤完成：

1. 运行新的资料冻结命令，从共同资料准备器取得真实本期数据，不调用旧版审阅、批准或方向生成：

```powershell
. .\dev-env.ps1
Set-Location .\03-python
.\.venv\Scripts\python.exe -B -m app.commands.fund_prediction_v2_sources `
  --run-dir <全新资料目录> --analysis-request <运行器返回的analysis-request.json>
```

`--analysis-request`可重复；也可使用重复的`--fund-code`。不指定两者时动态读取当前本人持仓。准备失败会保存具体缺口；基准不齐不把`source_ready`改成真；日期缺失不补造普通工作日。

2. 用输出的`selection.json`执行严格准备：

```powershell
.\.venv\Scripts\python.exe -B -m app.commands.fund_prediction_v2 prepare `
  --run-dir <全新审阅目录> --selection <资料目录\selection.json>
```

3. 真实阅读并分别写四周期分析，用`evaluate`检查：

```powershell
.\.venv\Scripts\python.exe -B -m app.commands.fund_prediction_v2 evaluate `
  --run-dir <审阅目录> --reviews-file <实际分析文件>
```

4. 在运行器返回的`review_path`保存`reviewed-trial-ref.json`，内容为`{"trial_directory":"实际审阅目录的绝对路径"}`；恢复原每日目录，由严格发布入口重新检查并追加正式记录。

新的第二版正式入口不接受旧V1 `review.json`来代替实际新审阅。检查分别报告已保存分析、带日期方向、半年条件意见、暂不判断及未完成；不能因有页面内容就称当天四周期全部预测完成。
