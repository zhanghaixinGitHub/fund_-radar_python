## 核心设计

业务结果按原数据库/快照契约读取。源资料复用同一来源版本的已有表示，缺少所需页面、排版或元数据时允许按需读取原件；新来源不以入库为前提。可变运行JSON及普通业务文件读取实际D盘版本。原件路径已迁空时，根据历史身份定位04-SourceFile，实际打开时校验摘要和长度；原件确实删除时兼容已有库内表示，不补造二进制。显式数据库验收仍只读库，显式原件验收不拿缓存冒充原件。

原件还在原业务路径时，按文件实体、长度、mtime/ctime识别版本变化并有界复用来源摘要；摘要不匹配即使用当前原件而非旧缓存。实际I/O、权限、损坏错误不吞掉。缓存命中不能作为所有归档原件完整或外接盘硬件健康的证明。历史原件尚存但仅缺某种表示时，可沿用已有按需解析缓存，不自动补提整套文档。

保存入口继续保留已有不可变文件/来源摘要校验，默认写调用方D盘业务目录；保存后的资料钩子不触发提取、搬迁或清理。旧来源已迁走的不可变引用继续防止误覆盖。对仅有库内表示的旧来源，不以重新构建伪原件满足读取。

04-SourceFile现存分类：`originals`为内容寻址原件；`manifests`为原业务路径与原件关系；`runs`为迁移与复核凭据；`staging`为既有解析/核验暂存。本次优先恢复读取关系，不在连接不稳定时重新物理布局百万级历史目录。未来如需清理或移动，另按实际引用与明确授权处理。
