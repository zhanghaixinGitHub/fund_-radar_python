## 服务契约

`POST /internal/v1/market-revisions` 是只读版本查询，不创建作业。沿用服务 Token 与拒绝浏览器 Origin 的边界。

请求 `items` 为 1–50 项，每项：`key`（唯一、最多 64 字符）、`fund_code`（6 位）、`start_date`、`end_date`、`kind`（`SIMULATION` 或 `LABEL`）。区间最长 3660 天，不接受未来日期、额外字段及个人账户/金额/订单信息。

响应包含 `calendar_revision` 和 `items[{key, revision, ready}]`。Java 校验条数、标识集合、重复项、摘要格式与就绪类型，异常时不推进水位。模拟范围超过 50 只时拆批。

内容摘要由数据库聚合净值原值、公告日、来源内容版本、分红与来源资格；不以最后同步时间或最新净值日期代替内容版本。`LABEL` 仅含基准日/目标日净值与目标日权益事件，无关日期数据变化不触发旧预测复盘。`SIMULATION` 额外包含目录信息及分红核验状态。接口不调用 Tushare。

Java 增加 Flyway `V28__direction_review_checkpoint.sql`，单独保存成功核对的版本，不修改不可变预测或结果证据表。
